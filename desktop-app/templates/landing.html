What the system does

Four surfaces over one pipeline — the inline badge for the person reading mail, the dashboard for the people defending the organisation.

Verdict on every message

Not just the bad ones. A visible safe score means “checked and clean”, so silence is never mistaken for safety.

Header & IP forensics

SPF, DKIM and DMARC results, relay-hop chain, domain age, ASN reputation and origin geography — resolved from local databases.

Campaign correlation

Template fingerprints link messages that arrived separately, surfacing one operation instead of five unrelated incidents.

Per-email forensic report

Every case opens into a standalone, printable report: verdict, weighted evidence chain, authentication table, relay path and ledger seal.

The detection cascade

Cheap checks first, the heavy model only when the answer is genuinely uncertain.

  1. Tier 0

    Gatekeeper — runs on every message

    A LightGBM classifier over engineered header, protocol and IP-trust features returns a fraud probability plus a distribution across threat categories. Clear-cut mail resolves here in milliseconds, and the category ranking decides what Tier 1 checks first.

  2. Tier 1

    Specialist adapters — only for ambiguous mail

    One ModernBERT-base encoder is held in memory, with a small independently trained LoRA adapter attached per threat category and detached again after the check. Categories are tried in Tier 0's probability order and the cascade stops at the first confirmation, so a case usually resolves in one or two checks rather than thirty.

  3. Chain

    Evidence scoring — never a single opaque number

    Each contributing factor is kept separately as {factor, contribution, explanation}, so a verdict can be handed to an investigator, to HR or to legal and defended line by line instead of taken on faith.

Tamper-evident storage

Every report is sealed into a hash chain

The moment a case is scored, its forensic content is hashed with SHA-256 and written into a block that also carries the hash of the block before it. Editing a stored verdict after the fact — changing a score, softening an evidence line, deleting an inconvenient case — breaks that block's hash and every hash that follows it, and the dashboard reports the chain as broken with the exact block identified.

It is the block structure of a blockchain used for what it is actually good at here: proving a record has not been altered since it was written. There is no external chain, no wallet and no network call — the proof recomputes from two files on this machine, which is what keeps it usable inside an air-gapped environment.

Where the data goes

The short answer is nowhere. The long answer has exactly one footnote, and it is stated plainly.

Analysis is local

The browser extension talks to 127.0.0.1 only. Message content and headers are scored on the same machine that opened the mail.

Enrichment is offline

Geolocation, ASN and hosting checks are answered from local IP databases, so no third party learns which addresses you looked up.

Storage is inspectable

Cases are plain JSONL on disk with a readable ledger beside them — no opaque database, no vendor export required to audit your own history.

The one exception

If campaign sync is switched on, a structural fingerprint and sender infrastructure — never content — may be shared to the organisation's own index so cross-inbox campaigns can be recognised.
